# تصویر زنده دوربین‌های MDVR (Meitrack) — راهنمای کامل

این سند پیاده‌سازی پخش زنده‌ی دوربین‌های MDVR (مانند MD300) در پلتفرم FleetVision را توضیح می‌دهد: معماری، راه‌اندازی، **کانفیگ دستگاه** و عیب‌یابی. پیاده‌سازی از پروژه‌ی مستقل md300 پورت و یکپارچه شده است.

## معماری

```
[دستگاه MDVR] ←TCP 5023 (GPRS)→ [device-gateway] ←Kafka← [fleet-management] ←REST← [داشبورد]
      │  (پس از دستور A9A)                          │ دکمه پخش: A9A + اتصال WS
      ↓ dialback TCP 6182                            ↓
[mdvr-streamer: پارسر 0x12 → NAL → ffmpeg(mpeg1video) → MPEG-TS] ←WS (nginx)─ پلیر JSMpeg روی canvas
```

- **دستگاه** یک اتصال GPRS به `device-gateway` (پورت 5023) نگه می‌دارد — همان اتصالِ تله‌متری و همه‌ی دستورات (A21، A9A، A9B و...).
- **A9A** از مسیر استاندارد فرمان ارسال می‌شود: داشبورد → `POST /api/v1/devices/:id/commands` → Kafka → device-gateway → دستگاه. کاتالوگ کامل ۷۸ دستوری MDVR (با فرم فارسی) در Command Center موجود است.
- دستگاه پس از A9A به **mdvr-streamer** (پورت 6182) وصل می‌شود و پکت‌های باینری 0x12 (پروتکل §3.16) می‌فرستد.
- streamer پکت‌ها را بازسازی می‌کند (الگوی COMPLETE + فرگمنت‌ها)، به ffmpeg می‌دهد و خروجی **MPEG-TS با کدک MPEG-1** را روی WebSocket باینری به مرورگرها می‌فرستد. پلیر **JSMpeg** روی canvas دیکد می‌کند.
  > نکته‌ی مهم: JSMpeg فقط دیکدر MPEG-1 دارد (هیچ پشتیبانی از H.264). به همین دلیل ffmpeg به mpeg1video ترنسکد می‌کند — ورودی H.264/H.265 هر دو پشتیبانی می‌شوند.

## سرویس‌ها و پورت‌ها

| سرویس | پورت | دسترسی | نقش |
|---|---|---|---|
| device-gateway | 5023/TCP | **عمومی** (دستگاه) | اتصال GPRS دستگاه + ارسال دستورات |
| mdvr-streamer | 6182/TCP | **عمومی** (دستگاه) | دریافت رسانه (dialback بعد از A9A) |
| mdvr-streamer | 3013 | داخلی (nginx) | وضعیت + WebSocket پلیرها (`/media-live/ws?imei=…`) |
| media-service | 3012 | داخلی (nginx) | کاتالوگ کانال‌های دوربین (`/api/v1/media/channels`) |

## راه‌اندازی استقرار (یک‌بار)

1. **کلید API گیت‌وی** (برای احراز IMEI دستگاه‌ها):
   ```bash
   node tools/provision-device-gateway-key.mjs
   # خروجی: FLEET_REGISTRY_API_KEY=fv_live_…  ← به infra/docker/.env اضافه کنید
   ```
2. `docker compose -f infra/docker/docker-compose.yml up -d --build`
   device-gateway، mdvr-streamer و media-service همه در compose تعریف شده‌اند.
3. اگر دستگاه از اینترنت وصل می‌شود، پورت‌های 5023 و 6182 باید به این سرور فوروارد باشند.

## کانفیگ دستگاه (خواسته‌ی اصلی)

### از طریق داشبورد (توصیه‌شده)
صفحه‌ی **Video → دکمه‌ی «تنظیمات دوربین»** کشوی راه‌اندازی ۴ مرحله‌ای را باز می‌کند:
1. انتخاب دستگاه (از رجیستری)
2. **A21** — تنظیم سرور GPRS (IP/دامنه، پورت 5023، APN اپراتور) — فرم با مقادیر همین سرور پیش‌پر شده است؛ وضعیت دستور (QUEUED→SENT→ACKED) نمایش داده می‌شود
3. ثبت کانال دوربین در کاتالوگ رسانه (برچسب + شماره کانال 1-4)
4. تست پخش زنده (A9A/A9B)

### با SMS (وقتی دستگاه GPRS وصل نیست)
به شماره‌ی SIM داخل دستگاه بفرستید:
```
A21,1,<IP-سرور>,5023,<APN>,,     ← تنظیم سرور (مهم‌ترین)
D11                               ← وضعیت دستگاه
A10,0                             ← موقعیت لحظه‌ای
```
سپس دستگاه را ری‌استارت کنید.

### الزامات دستگاه
- کدک دوربین: **H.264** (نه H.265 — هرچند H.265 هم سمت سرور پشتیبانی می‌شود، پهنای باند 4G برای H.264 بهتر است)
- Live Streaming و کانال دوربین فعال باشند
- APN درست اپراتور (از اپراتور SIM بپرسید)

## تست بدون سخت‌افزار — شبیه‌ساز

```bash
# دستگاه ساختگی: به گیت‌وی وصل می‌شود، A9A را می‌شنود، به streamer وصل و
# ویدیوی testsrc (ffmpeg) را به‌صورت پکت‌های 0x12 می‌فرستد
node tools/mdvr-simulator.mjs --imei 867191086416152
# سپس در داشبورد کانال را به دیوار اضافه کنید (خودکار A9A می‌فرستد)
```

## عیب‌یابی

| نشانه | بررسی |
|---|---|
| دستگاه وصل نمی‌شود | لاگ `docker logs fleetvision-device-gateway`؛ A21 درست؟ APN؟ پورت 5023 باز؟ |
| A9A می‌رود ولی ویدیو نمی‌آید | `docker exec fleetvision-web curl -s http://mdvr-streamer-service:3013/status` — دنبال `producing:true`؛ پورت 6182 از دید دستگاه باز است؟ (A9A باید IP عمومی بدهد — `VITE_MDVR_PUBLIC_HOST`) |
| تایل در «در حال اتصال» می‌ماند | کش مرورگر را پاک کنید (Ctrl+Shift+R)؛`/media-live/ws` در nginx باید Upgrade header داشته باشد |
| تصویر خراب/فریز | سیگنال شبکه‌ی دستگاه؛ در status خطای seq-gap ببینید |

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `GATEWAY_MEITRACK_PORT` | 5023 | پورت GPRS دستگاه‌ها |
| `MDVR_VIDEO_PORT` | 6182 | پورت dialback رسانه |
| `MDVR_MAX_STREAMS` | 32 | حداکثر استریم هم‌زمان |
| `FLEET_REGISTRY_API_KEY` | — | کلید سرویس (با اسکریپت provisioning بسازید) |
| `VITE_MDVR_PUBLIC_HOST` | hostname صفحه | IP/دامنه‌ای که در A9A به دستگاه داده می‌شود |
| `VITE_MDVR_PUBLIC_PORT` | 6182 | پورت تبلیغ‌شده در A9A |

## DMS / ADAS — هشدارهای پایش راننده

هشدارهای DMS (دوربین پایش راننده) و ADAS از رویداد **126** (`ADAS/DMS Alarm`) در پکت‌های CCE می‌آیند؛ جزئیات در پارامتر باینری `0xFE31` (نسخه پروتکل + نوع هشدار + نام عکس لحظه‌ی رخداد).

**زنجیره‌ی کامل (پیاده‌سازی شده):**
```
دستگاه (CCE event 126 + 0xFE31) → device-gateway (دیکد باینری + نگاشت نوع)
→ Kafka (telemetry.alarm.raw) → notification-service (هشدار نوع 'dms' + dedup 60s)
→ مرکز هشدار داشبورد (چیپ «DMS / پایش راننده» + فیلتر)
```

**انواع پشتیبانی‌شده:** خواب‌آلودگی (بحرانی)، بستن چشم، غیبت راننده (بحرانی)، حواس‌پرتی، زنگ‌زدن، مکالمه، سیگار، نوشیدنی، انسداد دوربین، برخورد از جلو FCW (بحرانی)، TTC، انحراف از خط، فاصله‌ی نامناسب HMW و…

علاوه بر DMS، همه‌ی رویدادهای جدول CCE (دزدی سوخت، دما، قطع ویدیو، ذخیره‌سازی، ترمز شدید و…) نگاشت شده‌اند. کانفیگ DMS دستگاه (دستور C90 و…) از طریق **ویزارد کانفیگ دستگاه** (صفحه‌ی Video → تنظیمات دوربین → دسته‌ی «هشدارها») انجام می‌شود.

**تست:** شبیه‌ساز هر ۴۵ ثانیه یک هشدار DMS چرخشی می‌فرستد (`--dmsInterval` برای تغییر).
