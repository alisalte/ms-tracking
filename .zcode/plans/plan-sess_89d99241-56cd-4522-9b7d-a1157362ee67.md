# Sprint B — Security & Tenant Isolation (implementation plan)

## Goal & guardrails
Make every backend service authenticated, authorization-aware, and tenant-isolated. Eliminate the "send `X-Tenant-Id` and read another tenant's data" attack. **Do not** modify gps-engine trip persistence beyond a required security fix; **do not** touch device TCP/UDP protocol auth; **do not** start Sprint C.

## Three architectural decisions (proceeding with recommended defaults)
1. **RBAC source = permissions embedded in the JWT.** Add a `permissions: string[]` claim at login + refresh. Downstream services read permissions from the verified token → stateless, zero iam-DB coupling, no per-request DB hit. Role changes call `RevocationStore.revokeUser()` (already exists, `session-store.ts:99`) → outstanding tokens die within TTL → client refreshes → fresh permissions. ~instant propagation.
2. **RLS = harden predicates + honestly document the bypass.** Replace every permissive `USING(true) WITH CHECK(true)` with a real tenant predicate as forward-ready hardening, **but** document that the app connects as the DB owner/superuser (`fleetvision`), so RLS is bypassed today and the **real enforcing boundary is the authenticated repo-layer `WHERE tenant_id` filter**. `vehicle_positions` stays RLS-off (Timescale conflict), repo-level only. No infrastructure/role-split redesign.
3. **Delivery = full sprint, one pass**, then `pnpm typecheck/build/test/lint`.

## WS1 — New shared package `@fleetvision/auth` (single source of truth)
Create `packages/auth/` (package.json mirroring `packages/web`, tsconfig, jest, src/index.ts, README). Promote identity's auth primitives here so nothing is duplicated:

- `AuthenticatedContext` (rename of `Principal`) — `{ userId, tenantId, tenantTier, roles, permissions, sessionId, jti, authMethod: 'JWT'|'API_KEY' }`, plus `getAuthContext(req)` + express `Request.auth` augmentation. (`api/shared/principal.ts` → here.)
- `JwtAuthGuard` — verifies Bearer JWT (signature/exp/iss/aud), checks `RevocationStore.isRevoked`, builds `AuthenticatedContext` from claims **including `permissions` read from the token** (drops the per-request `permissionsForUser` DB read). Supports a `@Public()` skip. Token-injection tokens (`TOKEN_VERIFIER`, `REVOCATION_STORE`) so each service supplies its verifier.
- `ApiKeyAuthGuard` (new) — accepts `Authorization: Bearer fv_…` when not a JWT, or `X-API-Key`. Resolves by prefix, argon2-verifies, checks active/expired, builds context with `authMethod:'API_KEY'`, `tenantId` from the key, `permissions` = key scopes. Backed by an `ApiKeyVerifier` port (default impl queries `iam.api_keys` via shared knex).
- `CompositeAuthGuard` (JWT-or-API-key) registered as the global `APP_GUARD`.
- `PermissionsGuard` + `@RequirePermissions()` + `permissionSatisfies` (moved here).
- `@Public()` decorator (Reflector metadata `IS_PUBLIC_KEY`).
- `@CurrentUser()` / `@CurrentTenant()` param decorators.
- Extended permission catalog: keep all `iam.*`/`billing.*`/`audit.*`; add `tracking.read`, `maps.read`, `maps.write`, `media.read`, `media.write`, `telemetry.gateway.manage` (only what existing endpoints need). Add these reads to `viewer`, reads+writes to `fleet-admin`, `tenant-admin` already `*`.
- `authConfigSchema` (zod): `JWT_SECRET` (min 32), `JWT_ISSUER` (default `fleetvision`), `JWT_AUDIENCE` (default `fleetvision` — **standardize platform-wide audience** so all services verify the same token; update `.env.example`).
- `AuthModule.forRoot({ audience })` wires `@nestjs/jwt` JwtService + providers, exports guards. Add `@fleetvision/auth` to root `tsconfig.json` references + `pnpm` resolves via workspace.

## WS2 — identity-service: token claims + propagation + adopt shared guard
- Extend `AccessTokenClaims` (`token-service.ts:15`) with `permissions: readonly string[]` (flows through `issuePair`'s `...claims` spread automatically).
- `LoginUseCase` (`login.use-case.ts`): inject `RoleRepository`; in `claims()` (L169) compute `permissions = await roles.permissionsForUser(tenantId, userId)` and embed.
- `RefreshTokenUseCase` (`refresh.use-case.ts`): inject `RoleRepository`; in `claimsFor()` (L81) compute + embed permissions (so refreshed tokens are current).
- `AssignRoleUseCase` (`user.use-cases.ts:96`): inject `RevocationStore`; after successful assign, call `revokeUser(userId, accessTtl)`. Update factory wiring (`auth.module.ts:219`). **Note gap:** no `RevokeRoleUseCase`/route and `RoleRepository.save` (role-permission edits) has no revocation side-effect — document as remaining risk; cover if a revoke path is added.
- `JwtAuthGuard` shared impl reads permissions from token → remove the per-request DB read. Keep `RevocationStore` revocation check.
- Drop per-controller `@UseGuards` from the 4 identity controllers (now global). Add `@Public()` to `login` (L61), `refresh` (L99), and health routes. Keep `@RequirePermissions` on business routes.
- `CreateApiKeyUseCase`: enforce scopes ⊆ caller's tenant permissions (domain comment claims this; not implemented today).
- **Bug noted (do not "fix" silently, but harden):** `isRevoked` returns false on Redis error (null compare) — currently open, not fail-closed. I'll make the guard treat Redis-unreachable as fail-closed for security endpoints and document it.

## WS5 — WebSocket authentication + tenant isolation
- **gps `realtime.gateway.ts`**: add `io.use` handshake verifying JWT (from `Authorization` or `auth.token`) via shared verifier → store principal on `socket.data`; reject on invalid/missing. Tighten CORS to configurable `GPS_WS_CORS_ORIGIN` (no `*`). On `subscribe(room)`: parse `tenant:<tid>:…`, require `tid === principal.tenantId`; reject cross-tenant (emit error, don't join). Same for `vehicle` rooms (tenant match; vehicle-level enforcement deferred — no vehicle registry exists).
- **media `signaling-gateway.ts`**: tighten CORS to `MEDIA_WS_CORS_ORIGIN` (no `*`). Keep the existing opaque signaling-token handshake (it's already room-bound). **Fix the mint source:** `StreamsController.openStream` currently trusts `body.userId` + `tenantOf(req)` header → replace with verified principal's `userId`/`tenantId` (WS6 closes the loop). `StreamManager.openSession` already accepts `userId` in opts.

## WS6 — API-key authentication path (closes the dead-code gap)
- `ApiKeyAuthGuard` in `@fleetvision/auth` (WS1). Endpoints accept JWT **or** API key. Default `ApiKeyVerifier` queries `iam.api_keys` by prefix cross-tenant (`withoutTenantContext`), argon2-verifies secret, checks `ApiKey.isActive()`, returns `{ tenantId, scopes, userId }`.
- Wire into `CompositeAuthGuard` (JWT first; if token isn't a JWT shape, try API key).
- Tests: valid key → allow; revoked → deny; tenant-A key → tenant-B resource → deny (tenantId from key, repo filters by it).

Use it in downstream tenant-scoped write paths to set `app.current_tenant_id` (defense-in-depth for RLS). Audit complete: position/trip/geofence/poi/channel repos already filter by tenant_id.

## WS8 — X-Tenant-Id / tenant switching
- Shared guard: on guarded requests, if `X-Tenant-Id` present and **≠ principal.tenantId** → `403` (unauthorized switch). If absent or equal → use principal tenant. This satisfies the switching test matrix (own→allow, other→403) without inventing multi-membership.
- Login/refresh keep using the header pre-auth (server-resolved via `resolveTenantId`, already validated).
- **Document:** real multi-tenant membership (a user in N tenants) is future work; today users are single-tenant. Frontend: backend is authoritative (JWT); optionally align `auth.store` to store server-returned `tenant_id` rather than the user-typed value (minor, security-correctness only — not a business feature).

## WS9 — RLS hardening (forward-ready) + honest docs
- Migration(s) replacing every `USING(true) WITH CHECK(true)` with: `USING (tenant_id = NULLIF(current_setting('app.current_tenant_id', true), '')::uuid) WITH CHECK (tenant_id = NULLIF(current_setting('app.current_tenant_id', true), '')::uuid)` (NULLIF → fail-closed 0-rows when GUC unset) across: `iam.*` (identity migration), `tracking.device_status/trip_events/idle_periods/parking_periods/engine_hours`, `tracking.geofences`, `geo.pois/addresses`, `media.video_channels/stream_sessions`. Add real policies for `geo.speed_limits` + `audit.audit_entries` (have tenant_id, no RLS today).
- **`vehicle_positions`: leave RLS disabled** (Timescale conflict), repo-level isolation, documented.
- **Prominent documentation:** with the single-superuser `fleetvision` connection, RLS is bypassed (superuser/owner) and is **not** the enforcing boundary today; enforcement = authenticated repo-layer filtering. RLS becomes effective once a non-superuser app role is introduced (future infra, out of scope). This complies with "don't use USING(true) as a security policy" (it no longer is) without redesigning infra.
