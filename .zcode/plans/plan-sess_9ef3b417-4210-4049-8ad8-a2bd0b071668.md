# انتقال تصویر زنده MD300 به ms-tracking

## یافته‌های کلیدی بررسی

**چیزهایی که از قبل در ms-tracking وجود دارد (و کار می‌کنند):**
- کاتالوگ کامل ۷۸ دستور MDVR در `fleet-management` (`meitrack-command-catalog.ts`) — شامل **A9A** (شروع استریم، ساخت struct باینری دقیقاً مثل md300)، **A9B** (توقف)، **A21** (کانفیگ سرور GPRS + APN) با فرم‌ها و برچسب‌های فارسی
- مسیر کامل فرمان: داشبورد → `POST /api/v1/devices/:id/commands` → Kafka → `device-gateway` (آداپتور Meitrack + انکود باینری `payload.hex`) → سوکت دستگاه
- `media-service` (NestJS): کاتالوگ کانال‌ها + سشن‌ها + توکن (Postgres + RLS) — ساخته شده ولی مستقر نیست
- VideoWall داشبورد: کامل با Tile/کنترل‌ها ولی استریم **mock**؛ نقطه‌ی سواپ (`openStream`، `useStreamSession`) طراحی شده
- **device-gateway و media-service اصلاً در docker-compose مستقر نیستند**

**چیزی که غایب است (همان هسته‌ی md300):**
1. پارسر پکت باینری رسانه (هدر 28-بایتی `0x12` — §3.16 پروتکل MDVR)
2. صفحه‌ی رسانه: TCP listener ویدیو → بازسازی NAL → ffmpeg (H.264/H.265→MPEG-TS) → WebSocket → پلیر JSMpeg
3. پلیر واقعی در مرورگر + UI راه‌اندازی/کانفیگ دستگاه

## معماری نهایی

```
[دستگاه MD300] ←TCP 5023 (GPRS)→ [device-gateway] ←Kafka← [fleet-management] ←REST← [داشبورد]
      │  (بعد از دستور A9A با آدرس streamer)                        │ دکمه پخش: A9A + اتصال WS
      ↓ dialback TCP 6182                                           ↓
[mdvr-streamer: پارسر 0x12 → NAL → ffmpeg → MPEG-TS] ←WS (nginx)────┘  پلیر JSMpeg روی canvas
```
دستگاه یک اتصال GPRS به gateway نگه می‌دارد (تله‌متری + همه‌ی دستورات). streamer فقط صفحه‌ی رسانه است — بدون Kafka، ساده و وفادار به live.js اثبات‌شده‌ی md300.

## فاز ۱ — پکیج پروتکل مشترک `packages/meitrack-media-protocol`
پورت TypeScript از `meitrack-protocol-parser.js`:
- `parseMediaPacket` (هدر 0x12: payloadType/dataType/packetFlag/BCD-IMEI/کانال/timestamp/طول)، `findPacketStart`، ثابت‌ها (PayloadTypes=98/99 H264/H265…، DataTypes، PacketFlags)
- پارسر/سازنده‌ی فریم GPRS متنی (`$$…*CS\r\n`) برای شبیه‌ساز
- تست‌های Jest با بردارهای طلایی (چک‌سام‌های مشخص در附录 PDF: A9A→E2, A9B→38)

## فاز ۲ — سرویس جدید `apps/mdvr-streamer-service`
پورت وفادار از `live.js` (بدون سرور فرمان — آن وظیفه‌ی gateway است)، Node+TS، وابستگی فقط `ws`:
- **Video TCP server** (6182): parse 0x12 → فیلتر I/P (حذف audio با payloadType اشتباه) → تشخیص کدک → بازسازی access unit (الگوی COMPLETE + فرگمنت‌های FIRST مثل md300) → seq-gap detection
- **FFmpeg manager**: spawn per-IMEI (`-f h264|hevc -i pipe:0 → libx264 ultrafast/zerolatency → -f mpegts pipe:1`)، ری‌استارت در تغییر کدک، teardown در قطع
- **WebSocket hub**: broadcast باینری MPEG-TS به بینندگان هر IMEI (room per imei)
- **REST**: `/health`، `/status`، `/status/:imei`
- Dockerfile: `node:22-bookworm-slim` + `apt ffmpeg`؛ compose با پورت عمومی 6182
- تست‌ها: بازسازی NAL با پکت‌های سنتزی، ffmpeg ساختگی با `FFMPEG_BIN=cat` برای تست pipe

## فاز ۳ — استقرار (compose + nginx)
- `device-gateway-service`: سرویس compose با `GATEWAY_LISTENERS=meitrack:tcp:5023` (پورت 5023 عمومی) + Kafka/Redis env
- `mdvr-streamer-service`: 6182 عمومی + HTTP 3013 داخلی
- `media-service`: 3012 داخلی (کانال‌ها/سشن‌ها، مهاجرت‌های Postgres)
- nginx: `/api/v1/media/` → media-service:3012 (حذف پیشوند)، `/api/v1/media-live/` → streamer:3013، و `/media-live/ws` → streamer با هدرهای Upgrade (اولین پروکسی WS در این nginx)
- به‌روزرسانی `.env`/`.env.example`

## فاز ۴ — داشبورد (پلیر واقعی + کانفیگ دستگاه)
- vendor کردن `jsmpeg.min.js` (از md300) + shim تایپ
- `video-stream.ts`: کلاینت واقعی `openJSMpegStream(wsUrl, canvas)` در کنار mock
- `useStreamSession`: مسیر واقعی برای کانال‌های `MEITRACK_MDVR`: ارسال A9A از طریق REST فرمان موجود (server=`location.hostname` یا `VITE_MDVR_PUBLIC_ENDPOINT`، tcpPort=6182، channel از کانال) → اتصال WS → پلیر → `streamKind:'real'`؛ باقی کانال‌ها mock با برچسب DEMO مثل امروز
- `LiveVideoPlayer`: حالت canvas (JSMpeg) در کنار `srcObject`؛ snapshot از canvas
- مسیر کانال‌ها: `video.api.ts` → `/media/channels` (واقعی + fallback)
- **کشوی «تنظیمات دوربین» در VideoWall** (خواسته‌ی دوم شما):
  1. انتخاب دستگاه (از /devices)
  2. فرم A21 (کانفیگ سرور GPRS + APN) با ارسال از طریق مسیر فرمان موجود + نمایش وضعیت (QUEUED→SENT→ACKED)
  3. ثبت کانال دوربین در media-service (deviceId، شماره کانال منطقی، label، IMEI)
  4. «تست پخش» → A9A + پیش‌نمایش زنده
  5. راهنمای فارسی داخل صفحه: جدول دستورات SMS، چک‌لیست پورت‌ها، الزام H.264 (برگرفته از DEVICE_SETUP.md)
- رشته‌های i18n fa/en؛ تست‌های vitest

## فاز ۵ — شبیه‌ساز + تأیید + مستندات
- `tools/mdvr-simulator`: اسکریپتی که خودش را دستگاه جا می‌زند: اتصال به gateway:5023 با فریم‌های AAA معتبر، شنیدن A9A، dialback به 6182 و استریم پکت‌های 0x12 حول یک ES H.264 (تولید با ffmpeg testsrc یا fixture)
- اجرای کل زنجیره روی stack واقعی Docker + بررسی بصری تایل زنده در مرورگر
- مستند `docs/implementation/MDVR_LIVE_VIDEO.md` (فارسی): کانفیگ دستگاه، پورت‌ها، env ها، عیب‌یابی

## پورت‌ها
| پورت | سرویس | دسترسی |
|---|---|---|
| 5023/TCP | device-gateway (meitrack listener) | عمومی (دستگاه) |
| 6182/TCP | mdvr-streamer (دایال‌بک ویدیو) | عمومی (دستگاه) |
| 3013 | mdvr-streamer HTTP/WS | داخلی (nginx) |
| 3012 | media-service | داخلی (nginx) |
