# Sprint 3 — Device Gateway Core

Builds **`device-gateway-service`** (Service Registry #7) per the canonical spec `docs/specs/06_Device_Gateway.md` — the multi-protocol TCP/UDP ingestion front tier. It terminates vendor binary protocols, authenticates devices, normalizes payloads to a canonical `DeviceMessage`, and forwards to Kafka.

Confirmed scope: **GT06 + stub plugin** adapters; **real Kafka/Redis, non-fatal at boot**.

## Conventions followed (from Sprints 1–2, identity-service as reference)

NestJS + DDD layers · branded ids (`@fleetvision/shared-kernel`) · zod crash-fast config · ESM with `.js` import specifiers · biome · transactional-outbox-style resilient Kafka · Redis store classes · knex migrations · jest `__tests__/*.spec.ts` · `OnApplicationShutdown` hooks · distroless Dockerfile · factory `forRoot()` modules.

## Key design decisions

1. **Fail-closed auth** (spec §6.1 invariant #1): no `DeviceMessage` published before AUTHENTICATED. Enforced and unit-tested.
2. **Real Kafka, non-fatal at boot** — same resilient pattern as the existing `kafka-outbox-relay.ts`: connect lazily, swallow boot errors, retry. So `pnpm dev`/tests run without Kafka up.
3. **DeviceRegistry as a port** — the durable `telemetry.telematics_devices` table is owned by the not-yet-built `device-management-service`; per spec §11 the gateway only *reads* it via gRPC. This sprint ships an in-memory implementation + the interface; the gRPC client is a later swap.
4. **One real adapter (GT06)** proves `detect/frame/decode/encode` end-to-end. The other 6 protocols are later-sprint adapter modules against the same contract — the PAL is the deliverable.
5. **Back-pressure over data loss** (spec §5.3): bounded connection pool + bounded internal queues; when full, stop accepting. Tested.
6. **Reuses shared-kernel** (`AggregateRoot`, `Brand`, `DomainEvent`, `GeoPoint`) — no reinvention.
