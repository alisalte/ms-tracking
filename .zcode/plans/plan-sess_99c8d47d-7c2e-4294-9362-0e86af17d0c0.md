## Sprint FE-2 — Identity UI

### Context: docs vs. backend reality (verified)

The design docs (`Authentication.md`, `IAM.md`, `Security.md`) specify a full identity system. The **actual backend** only implements login. Verified gaps:

| Screen | Doc spec | Backend |
|---|---|---|
| Login | ✅ | ✅ `POST /auth/login` |
| MFA Verify | ✅ | ❌ no MFA backend (just a `mfa_enabled` boolean, always false) |
| Register | ✅ | ❌ no `/auth/register` (only admin `POST /iam/users`) |
| Forgot/Reset Password | ✅ | ❌ no endpoints at all |
| Tenant Selector | — | ❌ forbidden by AUTH-BR-12 (tenant from JWT, never user input); no public lookup |
| Profile | ✅ | ⚠️ `GET /me` exists (email hardcoded `""`), no `PATCH /me` |

### Three scope decisions (using best judgment, no answer given)

1. **Scope = Full UI, mock the gaps.** This is a *frontend* sprint. I'll build all FE-2 screens as complete, accessible, i18n'd UI per the documented contract. Login stays fully functional. Register/MFA/forgot/reset/profile wire to typed API stub functions in `auth.api.ts` that throw a documented `NotImplementedError`, so backend integration is a one-file swap when endpoints land. This delivers a real, navigable UI without pretending unimplemented flows work.

2. **Adopt react-hook-form + zod** (the design doc mandates them). Install `react-hook-form@^7.84`, `zod@^4.4`, `@hookform/resolvers@^5.7` (all confirmed React-19-compatible). Migrate Login and build all new forms on them. Zod encodes the documented password policy (12+ chars, upper+lower+digit+symbol).

3. **Keep the tenant field on login** (backend requires `X-Tenant-Id`, throws without it). Document it as a known divergence from AUTH-BR-12. A standalone "tenant selector" screen would violate the security invariant, so "Tenant Selector" is read as the existing login-time tenant field — I'll polish it (auto-focus order, help text) rather than build a separate screen.

### Phase 1 — Foundation: forms lib + shared validation

- **Install** `react-hook-form`, `zod`, `@hookform/resolvers` (workspace-filtered to web-dashboard).
- **`src/lib/validation.ts`** (new): export a reusable `passwordSchema` (zod) encoding the Security policy — `min(12)`, `(/[a-z]/)`, `(/[A-Z]/)`, `(/[0-9]/)`, (`/[^a-zA-Z0-9]/`), with clear per-rule messages. Export `emailSchema`. These are shared across register/reset/change-password forms.
- **`src/lib/errors.ts`** (new): a `NotImplementedError` class and a small `isNotImplemented` guard, so stub endpoints fail loudly and predictably.

### Phase 2 — Types + API layer (extend the established camelCase-boundary pattern)

- **`src/types/auth.types.ts`**: add camelCase types for the new flows — `RegisterPayload`/`RegisterResponse`, `ForgotPasswordPayload`, `ResetPasswordPayload`, `MfaChallenge` (`{ mfaToken; availableMethods }`), `MfaVerifyPayload`, `UserProfile` (extends `User` with `displayName`, `username`, `mfaEnabled`, `status`, `lastLoginAt`). Add the matching `*Wire` snake_case types mirroring what the documented endpoints return.
- **`src/api/auth.api.ts`**: keep the existing `login`/`refresh`/`getMe`/`logout` (functional). Add typed stub functions for the unimplemented endpoints: `register`, `forgotPassword`, `resetPassword`, `getMfaFactors`, `verifyMfa`, each throwing `NotImplementedError('POST /auth/register not implemented in identity-service')`. Real wiring = replace the stub body with the `apiPost`+map call. Also note in comments the **202 MFA-required** contract the backend *will* return once MFA lands (`{ mfa_required, available_methods, mfa_token, expires_in }`).

### Phase 3 — Auth layout + form primitives

- **`src/components/form/PasswordTextField.tsx`** (new): MUI `TextField` wrapper with an eye/eye-off visibility toggle (lucide `Eye`/`EyeOff`), `react-hook-form` controller integration, and `aria-describedby` error wiring (the a11y checklist requires inline errors). Reused on login, register, reset, change-password.
- **`src/components/form/FormAlert.tsx`** (new): thin wrapper around MUI `Alert` for form-level errors/success, with ARIA live region.
- **`src/layouts/AuthLayout.tsx`**: extend to support a branded split-panel layout (branding/marketing on one side, form card on the other) per the login wireframe aesthetic, falling back to centered card on mobile. Keep the existing centered mode for the simpler pages. Add a "back to login" affordance pattern.

### Phase 4 — Login page upgrade (fully functional)

- Migrate `LoginPage` to `react-hook-form` + `zod` (email format + required; password required; tenant required).
- Add the **password visibility toggle** (PasswordTextField).
- Add **lockout/credential error** surfacing from the store (`AccountLockedError` → specific message; generic `InvalidCredentialsError` → generic message — no oracle, per ARR SEC-3).
- Add **"Remember this device"** checkbox (UI-only; wired to a flag for future session TTL use).
- Keep the tenant field (decision #3).
- Add navigation links: "Forgot password?" → `/forgot-password`, "Sign up" → `/register` (if tenant allows — UI shows the link; backend stub returns not-implemented).

### Phase 5 — Register, Forgot, Reset pages (UI complete, stubbed API)

Each: `react-hook-form` + `zod`, the documented fields, proper a11y, i18n, and routes under `AuthLayout`.

- **`src/pages/RegisterPage.tsx`** (`/register`): email, username (3–64), display name (optional), password (+ confirm). Uses `passwordSchema`. Links to login. Calls `register()` stub.
- **`src/pages/ForgotPasswordPage.tsx`** (`/forgot-password`): single email field; on submit shows a success state ("if the email exists, a reset link was sent") to avoid user enumeration. Calls `forgotPassword()` stub.
- **`src/pages/ResetPasswordPage.tsx`** (`/reset-password`): reads `token` from query string (`?token=`), new password + confirm, 30-min expiry messaging. Calls `resetPassword()` stub.

### Phase 6 — MFA Verify page (UI, stubbed)

- **`src/pages/MfaVerifyPage.tsx`** (`/mfa/verify`): reads `mfa_token` from query/route state. 6-digit OTP with auto-advance single-character inputs (the spec's "OTP auto-advance inputs"), a method switcher (TOTP / WebAuthn / backup code — TOTP default), rate-limit messaging. Calls `verifyMfa()` stub. Routes back to login on failure/expiry.

### Phase 7 — User Profile page (read-only from /me + stubbed edit)

- **`src/pages/ProfilePage.tsx`** (`/account/profile`, protected, inside AppLayout): display profile (id, email, tenant, roles, permissions) from the auth store's `User`. Since `GET /me` currently returns `email: ""`, show the email from the login response (already in the store) and note the `/me` hydration gap. Add a read-only "Security" summary section (MFA status: "Not enforced" reflecting the always-false backend flag; last login). Add a disabled "Edit profile" affordance with a tooltip explaining the backend has no `PATCH /me` yet — honest about the gap rather than a fake editable form.
- Add a **route entry in the top-bar user menu** ("Profile") and a nav route.

### Phase 8 — Router + i18n

- **`router/index.tsx`**: add public routes `/register`, `/forgot-password`, `/reset-password`, `/mfa/verify` under `AuthLayout`; add protected `/account/profile` under `AppLayout`.
- **i18n**: add all new strings to both `en/common.json` and `fa/common.json` (validation messages, field labels, button text, success/error states, MFA labels). RTL-safe (already wired from FE-1).

### Phase 9 — Tests

- **`__tests__/auth.api.spec.ts`**: extend — assert the stub endpoints throw `NotImplementedError` with the documented path, and that the existing mapping tests still pass.
- **`__tests__/validation.spec.ts`** (new): unit-test the zod `passwordSchema` — accepts a strong password, rejects each weak variant (missing upper/lower/digit/symbol, < 12 chars) with the right message.
- **`__tests__/LoginPage.spec.tsx`** (new): render the form with `react-hook-form`, assert the password toggle works, validation shows errors on empty submit, and successful submit calls `login` and navigates. Mock `@/api/auth.api` (no network, same pattern as FE-1).
- Keep the existing FE-1 tests green.

### What I am NOT doing (deliberate)
- Building a standalone tenant-selector screen (forbidden by AUTH-BR-12, no backend support).
- Real MFA enrollment/TOTP/WebAuthn (no backend) — the verify page is UI-only against the documented contract.
- A working editable profile (no `PATCH /me` backend) — profile is read-only with honest "not available" affordances.
- Reconciling the `/me` `email: ""` backend bug — that's a backend fix; the UI uses the login-response email.
- Admin Users & Roles management table (that's a separate admin-portal concern, not FE-2 self-service identity).
