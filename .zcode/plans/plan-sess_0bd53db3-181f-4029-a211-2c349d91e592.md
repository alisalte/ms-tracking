# Sprint C — Device & Fleet Management: Implementation Plan

## Goal
Create `fleet-management-service` (Fleet/Vehicle/Device domain, persistent + tenant-aware), wire the device-gateway to resolve device identity from it over **HTTP** (confirmed), and prove the full `device → gateway → Kafka → gps-engine → TimescaleDB` chain with trusted identity. Existing telemetry pipeline stays untouched; only identity *resolution* improves.

## Key architectural decisions (documented in the sprint doc)
- **Device lifecycle status** = `ACTIVE | SUSPENDED | DECOMMISSIONED | UNPAIRED` — reuses the gateway's existing `DeviceStatus` (the authorization/lifecycle status, deliberately *separate* from connection state ONLINE/OFFLINE in `tracking.device_status`). §9 satisfied.
- **IMEI is GLOBALLY unique** (physical identity; the registry resolves IMEI→device cross-tenant before tenant is known). `fleet.devices.imei` gets a global unique index. §10.
- **Gateway→fleet resolution = HTTP** behind the existing `DeviceRegistryPort`. Gateway never touches fleet's schema. Only on L3 cache miss (L1 30s / L2 Redis 5min already exist) → ~1 call/device/5min, never per-packet. §17/§22.
- **Connection state** (connected_at/last_seen_at/disconnected_at on `fleet.devices`) updated by a **fleet-service Kafka consumer** of the existing `telemetry.session.lifecycle` topic (AUTHENTICATED→connect, ACTIVE/touch→last_seen, DISCONNECTED→disconnect). Gateway stays a pure producer; no new event model. §21/§29. Not per-packet (gateway only emits transitions).
- **Cache invalidation** = TTL-bounded (30s/5min). Disable/reassign staleness window ≤30s documented as the chosen safe strategy (§29 explicitly allows TTL when event-driven invalidation isn't justified). No new invalidation channel.
- **Delete = archive/disable, never hard-delete** (device DELETE→DECOMMISSIONED; fleet/vehicle DELETE→ARCHIVED status). Telemetry history in `tracking.vehicle_positions` is never destroyed. §27.
- **Pagination** = cursor-based via `shared-kernel` `Page<T>`/`encodeCursor`/`decodeCursor` (the codebase's mandated standard). §15.
- **Audit** = reuse `audit.audit_entries` via a ported `AuditRepository.append(trx,…)` called inside each mutating transaction (no second audit system). §28.
- **Resolve endpoint security**: `GET /devices/resolve?imei=` is **API-key-only** (asserts `authMethod==='API_KEY'`, rejects JWTs) + requires a new `device.registry.resolve` scope granted *only* to the gateway's service API key — so no user (not even tenant-admin via wildcard) can enumerate cross-tenant devices. §33.

## B. New service `apps/fleet-management-service/` (mirrors gps-engine conventions)
- `package.json`/`tsconfig.json`/`jest.config.js` (copy gps-engine; deps minus socket.io; +`kafkajs` for the session consumer).
- `src/main.ts`, `src/app.module.ts` (ConfigModule→Logger→Persistence→Redis→AuthModule.forRoot→Health→FleetManagementModule.forRoot), `src/config/fleet-management.config.ts` (`baseConfigSchema.merge(authConfigSchema).merge({DBURL,REDISURL,FLEET_KAFKA_*})`).
- Add `{path:"apps/fleet-management-service"}` to root `tsconfig.json` references.
- **Migration** `20260814100000_create_fleet_schema.js` — schema `fleet`:
  - `fleets`(id,tenant_id,name,code,description,status,status checkIn[ACTIVE,ARCHIVED],version,ts) + unique(tenant_id,code)
  - `vehicles`(id,tenant_id,fleet_id FK→fleets RESTRICT,name,code,plate,vin,status[ACTIVE,ARCHIVED],version,ts) + unique(tenant_id,code),(tenant_id,plate),(tenant_id,vin)
  - `devices`(id,tenant_id,imei **global unique**,serial_number,manufacturer,model,protocol checkIn[gt06,jt808,meitrack,stub],status[ACTIVE,SUSPENDED,DECOMMISSIONED,UNPAIRED],last_seen_at,connected_at,disconnected_at,version,ts) + idx(tenant_id,status),(tenant_id,protocol),(tenant_id,manufacturer)
  - `vehicle_devices`(id,tenant_id,vehicle_id FK,device_id FK **unique**(≤1 vehicle/device),role,is_primary,bound_at,unbound_at,version,ts) + partial unique(vehicle_id) WHERE is_primary
  - RLS permissive stubs + a harden migration (`20260814110000_harden_fleet_rls.js`) with the fail-closed `tenant_id = current_setting(...)` predicate (matches Sprint B convention).
- **Domain** (`domain/{fleet,vehicle,device,binding}/*.types.ts`): lightweight types + `Imei` value object (15-digit + Luhn), `PROTOCOLS` const from gateway adapter ids.
- **Validation** (`application/validation/schemas.ts`): zod create/update for fleet/vehicle/device (names, codes, plate, VIN, IMEI+Luhn, protocol enum). Reused by controllers + tests.
- **Repositories** (`infrastructure/persistence/*.repository.ts`): plain classes `(knex: Knex)`, `withSchema('fleet')`, `?::uuid` binds, `WHERE tenant_id`, cursor paging; `DeviceRepository.resolveByImei(imei)` (cross-tenant, the source of truth for the resolve endpoint); `AuditRepository` ported from identity.
- **Application services** (`application/{fleet,vehicle,device,binding}.service.ts`): orchestrate create/update/list/get/archive + bind/unbind inside `withTenantContext` transactions w/ audit + cross-tenant guard + duplicate-binding prevention.
- **Kafka consumer** `infrastructure/kafka/session-lifecycle-consumer.ts`: consumes `telemetry.session.lifecycle`, updates `fleet.devices` connection columns (mirrors gps-engine consumer pattern; non-fatal at boot).
- **Controllers** (`api/*.controller.ts`) `@Controller('api/v1/...')`, `@CurrentTenant()`/`@CurrentUser()`, `@RequirePermissions`, `ZodValidationPipe`, `{data}`/`{data,nextCursor}`:
  - Fleets: POST/GET/GET:id/PATCH:id/DELETE:id (+filters status,search)
  - Vehicles: same (+filters fleetId,status,search) + GET /vehicles/:id/devices
  - Devices: same (+filters status,protocol,manufacturer,vehicleId,imei,search) + GET /devices/:id/vehicle + **GET /devices/resolve?imei=** (API-key-only service endpoint)
  - Binding: POST/DELETE /vehicles/:id/devices/:deviceId
- **Module/DI** (`api/fleet-management.module.ts` + `api/tokens.ts`): factory providers injecting `KNEX_TOKEN`/`REDIS_TOKEN`.

## C. device-gateway persistent (HTTP) registry
- `infrastructure/registry/http-device-registry.ts` — implements `DeviceRegistry`; `resolve(imei)` = `fetch(FLEET_REGISTRY_URL/devices/resolve?imei=, {headers:{'X-API-Key':FLEET_REGISTRY_API_KEY}})`, parses `{found,device,tenantActive}`; fail-closed (network/parse error → `{found:false}`, logged). `tenantActive` from the resolve response.
- `config/device-gateway.config.ts` — add `FLEET_REGISTRY_URL` (default `http://localhost:3006`) + `FLEET_REGISTRY_API_KEY` (default ''→fail-closed if unset).
- `api/gateway.module.ts` — `DEVICE_REGISTRY` provider → `HttpDeviceRegistry` (injects `GATEWAY_CONFIG`). `InMemoryDeviceRegistry` retained for unit tests (constructed directly; existing tests unaffected).
