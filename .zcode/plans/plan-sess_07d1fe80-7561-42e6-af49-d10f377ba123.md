# FleetVision Frontend — Complete CRUD for Vehicles / Drivers / Devices / Groups

## Ground truth (verified by codebase exploration)
- **Backend reality:** No vehicle/driver/device/group controllers exist in ANY backend service. All four list/detail hooks in `asset.api.ts` are mock-backed (`resolveMock`). Only `identity-service` (users/tenants) and `geofence` (map-engine) have real backends.
- **Task rule:** "Do not create fake CRUD functionality… use the real Backend API if it exists; if it does not exist, create a typed API contract/interface and clearly document the dependency instead of inventing fake behavior."
- **Decision:** Build **real mutation hooks** hitting the documented REST endpoints, using `withMockFallback` (the proven `admin.api.ts`/`geofence.api.ts` pattern) so they call the real API in production and gracefully fall back to mock in dev when the server is down. NO fake local-only mutations. Each hook + endpoint is documented as a typed contract.
- **No notification/confirm system exists today.** Task requires success/error notifications + delete confirmation → introduce a lightweight MUI Snackbar context (zero deps) + a reusable `ConfirmDialog`.

## Architecture patterns I'll follow (all proven in-repo)
- **Form pattern:** `react-hook-form` + `zod` + `@hookform/resolvers` + `<Controller>` + `<FormAlert>` (the LoginPage/RegisterPage pattern, NOT the GeofenceDialog useState pattern).
- **Mutation pattern:** `useMutation<TEntity, Error, TPayload>` with `mutationFn` via `apiPost`/`apiPut`/`apiDelete`, `onSuccess`/`onSettled` → `qc.invalidateQueries({ queryKey: queryKeys.assets.all })` (the geofence pattern). For optimistic status changes, the existing `useVehicleStatusAction` skeleton.
- **List pattern:** keep `useVehicles/useDrivers/useDevices/useGroups` mock-backed fetchers but route them through `withMockFallback(realFetch, mockFetch)` so a real backend is auto-used when present.
- **Query keys:** centralized — extend the `queryKeys.assets` factory with `groupDetail(id)`.

## Phase 2 — API layer: real CRUD hooks (typed contracts) — `src/api/asset.api.ts`

For each entity, add typed mutation hooks wired to the documented REST endpoint via `apiPost`/`apiPut`/`apiDelete`, each invalidating `queryKeys.assets.all`. Each hook documents its backend dependency in a JSDoc comment.

**Vehicles** (`/fleet/vehicles`):
- `useCreateVehicle()` — `useMutation<Vehicle, Error, CreateVehiclePayload>` → `apiPost('/fleet/vehicles', mapToWire)`.
- `useUpdateVehicle()` — `useMutation<Vehicle, Error, { id; changes: UpdateVehiclePayload }>` → `apiPut('/fleet/vehicles/${id}', …)`.
- `useDeleteVehicle()` — `useMutation<void, Error, string>` → `apiDelete('/fleet/vehicles/${id}')`.
- Refactor the existing `useVehicleStatusAction` to use the new `useUpdateVehicle` internally (keep its optimistic UX).
- Convert list/detail fetchers to `withMockFallback`.

**Drivers** (`/drivers`): `useCreateDriver`, `useUpdateDriver`, `useDeleteDriver`, `useAssignDriverVehicle({ driverId, vehicleId })`, `useUnassignDriverVehicle({ driverId })` (assign/unassign → `apiPostNoContent`).

**Devices** (`/telemetry/devices`): `useCreateDevice`, `useUpdateDevice`, `useDeleteDevice`, `useAssignDeviceVehicle`, `useUnassignDeviceVehicle`.

**Groups** (`/fleet/groups`): `useCreateGroup`, `useUpdateGroup`, `useDeleteGroup`, `useGroupDetail(id)` + `groupDetail(id)` query key (currently missing).

All hooks: real API in prod, `withMockFallback` ensures graceful dev fallback. No fake behavior.

## Phase 3 — Reusable form drawer (NEW) — `src/components/assets/AssetFormDrawer.tsx`
- One shared right-slide-over drawer (`anchor="right"`, width 480) reused for create + edit across all four entities.
- Props: `open`, `mode: 'create'|'edit'`, `entity: AssetTab`, `record?: TEntity` (for edit prefill), `onClose`, `onSuccess`.
- Internally selects the right zod schema + field-set per `entity`. Each field uses `<Controller>` + MUI `<TextField>`/`<Select>`/`<Switch>`.
- Shows `<FormAlert severity="error" message={serverError}>`, submit button with `isPending` → `common.submitting`, cancel, and "unsaved changes → confirm discard" via ConfirmDialog on close.
- Calls the matching create/update hook, then `toast.success` + `onSuccess()` (which invalidates the query via the hook) + closes.
- Validation, required indicators (`*`), helper text, and loading/disabled states per the task spec.

Field sets per the existing domain model (only fields the types support — no invented fields):
- **Vehicle:** licensePlate*, vin*, make*, model*, year*, type*, fuelType, color, status, groupId, deviceId, notes-free-text(N/A — type has no `notes` field, so omitted to honor "don't expose fields the backend doesn't support").
- **Driver:** firstName*, lastName*, email, phone, employeeId, licenseNumber*, licenseClass*, licenseExpiry*, status, assignedVehicleId.
- **Device:** serialNumber*, deviceType*, manufacturer, model, imei, firmwareVersion, reportingIntervalSec, status, boundVehicleId.
- **Group:** name*, description, vehicleTypeFilter, status.

## Non-goals / honest limits
- Backend endpoints for vehicles/drivers/devices/groups do **not** exist, so create/update/delete will return network errors in production until those services ship. The hooks are real and ready; `withMockFallback` keeps the UI demoable in dev. This is documented, not faked.
- "Configure", "Send Command", and "Manage Members" have no backend and no typed write contract beyond `types/command.types.ts` — surfaced as disabled/pending per the task's "don't fake it" rule.
- No new runtime dependencies (Snackbar is hand-built on MUI).
